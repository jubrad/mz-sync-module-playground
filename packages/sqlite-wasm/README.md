# @mz-web/sqlite-wasm

Browser-specific wa-sqlite runtime for `@mz-web/sink-sqlite`. Runs SQLite in a Web Worker via WebAssembly.

## Install

```bash
npm install @mz-web/sqlite-wasm @mz-web/sink-sqlite
```

## Usage

```typescript
import { WasmSqlite } from '@mz-web/sqlite-wasm'
import { MzSqliteSink } from '@mz-web/sink-sqlite'
import WorkerURL from '@mz-web/sqlite-wasm/worker?worker&url'  // Vite

const db = new WasmSqlite({ workerUrl: WorkerURL })
await db.init()

const sink = new MzSqliteSink({ db })
// ... register with subscribe client

// Query
const rows = await db.query('SELECT * FROM my_table')
```

## Worker Loading

The worker script needs to be loaded by your bundler. The pattern varies:

**Vite:**
```typescript
import WorkerURL from '@mz-web/sqlite-wasm/worker?worker&url'
new WasmSqlite({ workerUrl: WorkerURL })
```

**Webpack 5:**
```typescript
new WasmSqlite({ workerUrl: new URL('@mz-web/sqlite-wasm/worker', import.meta.url) })
```

**Manual:**
```typescript
new WasmSqlite({ workerUrl: '/path/to/sqlite-worker.js' })
```

## Architecture

```
Main Thread                     Web Worker
───────────                     ──────────
WasmSqlite                      wa-sqlite WASM (:memory:)
  │                                  │
  ├── exec(sql) ──postMessage──► sqlite.exec(db, sql)
  │                ◄──────────── {type:'done'}
  │
  └── query(sql) ──postMessage──► sqlite.exec(db, sql, cb)
                   ◄──────────── {type:'result', rows}
```

The worker is a dumb SQL executor — no table awareness, no schema logic. All SQL is generated by `@mz-web/sink-sqlite` and sent as strings.

## API

```typescript
const db = new WasmSqlite(opts?: { workerUrl?: string | URL })
await db.init()                    // load WASM, open :memory: DB
await db.exec(sql)                 // execute DDL/DML
const rows = await db.query(sql)   // execute SELECT, return objects
db.destroy()                       // terminate worker
```
